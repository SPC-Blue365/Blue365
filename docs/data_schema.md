## 2. 핵심 컬럼

### ① 광산 (Mine)
- `채굴일자`(date), `채굴시간(교대)`[1·2·3차] 또는 `시작시간`/`종료시간`
- `공정구분` = **기존 / 신설 / 운휴** (라인 구분) ✅
- `OSP적재구역` = 채굴물을 적재한 품위 구역코드 ✅ (복합코드 존재: "50/55", "55-45", "100-0" 등 → 한 교대에 여러 구역 적재)
- `CaO품위`, `MgO품위`(%), `이송물량(톤)` (49Q는 object형+'-' 혼입 → 정제 필요)

### ② OSP (인출)
- `일자`(date), `인출시간`(time)
- `공정구분`: 기존시트=전부 '기존' ✅ / 신설시트=전부 NaN(시트명으로 '신설' 보정 필요)
- `P/W1호~P/W4호` = **인출 품위 구역코드**로 추정(값 20~95, 광산 OSP적재구역과 동일 어휘) ❓
  - 기존라인 → P/W1·2호 사용 / 신설라인 → P/W3·4호 사용 ✅ (구조적 분리 확인)
- `인출량`(톤) = 그 인출 회차 총량 ✅ (구역별 배분 규칙 ❓)

### ③ 야드 (Yard)
- `일자`, `시간`, `CaO`, `MgO`(%), `적재물량` (CNA=TPH / 45Q=B/S, 단위 상이 ❓)
- `Yard` 컬럼: 두 시트 모두 전부 결측 → 미사용/플레이스홀더

## 3. Join Key (식별자) — ✅ 확정 (사용자 확인)

| 축 | Key | 규칙 |
|----|-----|------|
| 라인 | `공정구분` (기존/신설) | 기존→P/W1·2호, 신설→P/W3·4호 |
| 시간 | 일자 + 시각 → datetime | 시간창(1h) 집계 후 Time-Lag 정렬 |
| 공간(품위) | `OSP적재구역` ↔ `P/W호` (구역 20~95) | 광산 구역-품위 평균 → OSP 인출에 예상 CaO 부여 |
| 배분 | 인출량 ÷ 구역수 (균등) | 사용자 확정 |
| 최종 목표 | `CNA data` | 야드 적재 품위 기준 (45Q/47Q/49Q = 채굴구역 3곳) |

## 4. Time-Lag 규칙 — 🔬 데이터 추정 (1차)

- 방법: OSP 시간별 예상CaO를 지연시키며 야드 CaO와 피어슨 상관 최대 지연 탐색 (`estimate_time_lag`).
- **1차 결과: 최적 지연 ≈ 11시간, 그러나 상관 0.17로 약함.** → §7 참조. 매칭 신호 강화 필요.

## 6.5 도메인 확정 (2026-07-23, 사용자) ⭐️ 중요 정정
- **기존 ≠ 신설 = 서로 다른 야드**: 기존 인출 → **4-5K 킬른** 야드 / 신설 인출 → **6-7K 킬른** 야드. → 절대 합치지 않고 라인별 분리 모델링.
- **P/W1~4호 = 인출 지점(위치)**, 품위 등급 아님. 지점당 50% 균등 인출. (구역숫자 20~95는 위치ID)
  - 검증: 구역숫자 vs CaO 상관 = -0.001, 구역 내 CaO std 2.58 → 숫자는 품위 무관 확인.
- **품위 매칭은 시간인지로**: 지점의 품위는 '그 지점에 최근 적재된 광산 품위'(merge_asof)로 부여.
- **야드 페어링(데이터 상관 근거)**: 기존↔`CNA data`, 신설↔`45Q 감마레이 data`.
  - ❓ 45Q를 앞서 '채굴구역'으로 답했으나, 데이터 구조·상관은 45Q가 신설 야드임을 시사 → 최종 확인 필요.

## 7. 매칭 파이프라인 결과 & 한계 ⭐️ (2차: 라인 분리 + 시간인지)

| 라인→야드 | Time-Lag | 상관 | 설명력 천장(R²=corr²) | 선형 MAE vs naive |
|-----------|:-------:|:----:|:---------------------:|:-----------------:|
| 기존→CNA (4-5K) | 8h | +0.34 | 0.11 | 1.01 vs 0.91 |
| 신설→45Q (6-7K) | 9h | +0.39 | 0.13 | 1.49 vs 1.56 |

- **진전**: 라인 분리로 상관 0.17 → 0.34~0.44 (물리적으로 타당한 신호 확인).
- **정직한 한계(천장)**: 상류(광산품위+인출지점)가 야드 CaO 변동의 **약 11~13%만 설명**. 목표(±0.5) 제어에는 부족.
- **원인 진단**: ① 야드 시간의 **25%만** OSP 인출기록 존재(버퍼/직송 미확인) ② 야드 CaO 지속성 큼(자기상관 1h≈0.73) → 상류보다 야드 내부동역학이 지배 ③ 지점→품위가 일단위·75% 커버리지로 거침.
- **신호 강화에 필요한 것(사용자/데이터)**: OSP↔야드 버퍼/직송 여부, 야드 추가 투입원, 인출지점 실측 품위.

- 구현: `src/data/clean.py`(정제) + `src/matching/pipeline.py`(매칭). 스크립트 `scripts/build_matched_dataset.py`.
- 산출: `data/processed/matched_hourly.csv` (148 시간행 × 14열), OSP 예상CaO 매칭 커버리지 100%(라인 433/전역 22).
- **한계(정직 보고)**: OSP 예상CaO ↔ 야드 CaO 상관 0.17 (약함). 원인 가설:
  1. **정적 구역-품위 테이블** — 구역(파일)은 시간에 따라 다른 품위로 재적재되는데 6주 평균을 써 시간정보 소실. → **시간인지(most-recent-loading) 재고 모델**로 개선 필요.
  2. Time-Lag가 상수 아닐 가능성(물량 의존).
  3. 야드 시간내 변동이 큼(시간 집계로 소실).
- **다음 개선**: 구역별 '최근 적재 품위'를 인출시각 기준으로 매칭(재고 추적) → 상관/예측력 향상 기대.

## 5. 목표 & 제약 + ⭐️핵심 발견

- **목표**: 야드 적재 CaO 평균 44.6%, std ≤ 0.5
- **CaO 실측 통계**:
  | 소스 | n | 평균 | std | min | max |
  |------|---|------|-----|-----|-----|
  | 49Q광산 | 141 | 46.09 | 2.96 | 38.7 | 51.9 |
  | 47Q광산 | 59 | 45.56 | 0.46 | 43.9 | 46.7 |
  | **CNA야드(최종)** | 20,952 | **44.67** | **1.85** | 25.0 | 54.2 |
  | 45Q야드 | 3,839 | 45.40 | 2.26 | 38.4 | 53.0 |
- ⭐️ **야드 CNA 평균(44.67)은 이미 목표(44.6)에 근접 — 진짜 문제는 '분산(std 1.85)'을 0.5로 줄이는 것.**
  → ML 목표는 평균 이동이 아니라 **변동성 제어(안정화)** 에 초점.
- CNA min 25.0 = 센서 드롭아웃/이상치 가능성 → 검증 게이트 점검 대상.
