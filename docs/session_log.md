# 세션 로그 — 석회석 광산-야드 CaO 추적·예측 시스템 구축

> 이 문서는 프로젝트를 구축한 대화 세션의 내용·의사결정·결과를 정리한 기록입니다. (2026-07-23)

---

## 1. 프로젝트 개요
- **목표**: 광산 채굴 → OSP 적재/인출 → 야드 적재까지 CaO(생석회) 품위를 추적 매칭하고, 하이브리드 ML로 예측·제어.
- **품질 목표**: 야드 적재 CaO 평균 44.6%, 표준편차 0.5 이내.
- **작업 방식**: Claude Code 멀티에이전트(Main/Data-Analyst/Matching/ML/Research/Synthesis) + 세션 간 핸드오프.

## 2. 진행 타임라인 (단계별)
1. **프로젝트 골격 + CLAUDE.md(헌법) 작성**: 디렉토리 구조, 멀티에이전트 규칙, 절대준수 원칙(가상데이터 금지·불확실하면 질문·재현성).
2. **데이터 보관 정책 = 로컬 전용 확정**: 저장소 공개(Public)로 확인 → 민감 데이터는 GitHub에 절대 커밋 안 함. `.gitignore` + `BLUE365_DATA_DIR` 라우팅.
3. **데이터 로더 + 검증 게이트 구현**: `inspect_excel`, 검증(CaO 범위·음수물량·시간역전·Key 중복).
4. **데이터 수령·EDA**: `data_v1.xlsx` 6개 시트(광산 49Q/47Q, OSP 기존/신설, CNA, 45Q).
5. **매칭 파이프라인**: 시간인지(최근 적재품위) 지점→품위 매칭 + Time-Lag 상관추정 + 통합 데이터셋.
6. **도메인 정정 반영**: 기존/신설 = 서로 다른 야드(4-5K/6-7K 킬른), P/W = 인출지점, 야드 페어링 기존↔45Q·신설↔CNA.
7. **하이브리드 예측 모델**: 라인별 AR(자기회귀) + 상류. 시계열 교차검증.
8. **10개 모델 벤치마크 → Ridge 확정** + 재벤치마크 거버넌스.
9. **운영 도구화**: 모델 저장, 경보 엔진, 모니터 CLI, Streamlit 대시보드.
10. **대시보드 확장**: Sankey 추적도 탭 · 관리도(제어차트) · 경보 이력 로그.
11. **차트 날짜 형식**: x축 `2026/07/24` 슬래시 형식 적용.
12. **야드변경 추적**(신규 시트 2개): 라인→야드(Y1/Y2) Sankey + **CaO/MgO 버튼 토글** + 변경일자별 CaO·MgO 추이. (누적 인출물량 대체)

## 3. 주요 의사결정 (사용자 확인)
- 문서 언어 **한국어**, 리포트 **MD/HTML/PPTX/Notion**.
- 데이터 보관 **로컬 전용**(원격 커밋 금지).
- P/W 인출 **50% 균등 배분**, 최종 목표 기준 **CNA**(단, 야드 페어링은 이후 기존↔45Q/신설↔CNA로 확정).
- 하이브리드 = **예측(경로1, 메인) + 최적화(경로2, 향후 데이터 축적 시)**.
- 운영 예측 모델 **Ridge 확정**, 데이터 축적 시 **재벤치마크**로 재추천.
- 이메일 알림은 **보류**(기밀·SMTP).

## 4. 핵심 발견 (정직 보고)
- 야드 CNA 평균 44.67%(목표 근접) but **표준편차 1.85** → 과제는 "변동성 축소".
- 상류(광산품위+인출지점) → 야드 CaO **상관 0.17**, 라인 분리 후 0.34~0.39. **설명력 천장 R²≈0.13**.
- **야드 CaO 지속성(자기상관 1h≈0.73)** 이 예측력의 핵심 → AR 모델이 최적.
- 10개 모델 비교: **선형(Ridge)이 최적**, 부스팅(XGBoost/LightGBM)은 소표본 과적합으로 열위.
- 예측 성능: 신설/CNA MAE 0.80, 기존/45Q 1.04. **목표 MAE<0.5 미달** — 원인은 상류 제어정보 부족(모델이 아니라 데이터 한계).
- 결론: 현재는 **실시간 모니터링·조기경보**로 실무 유용. 처방적 배합제어는 데이터 축적 후.
